## Reacties van Nextcloud op GitHub

**Op PR 66355** ([reactie van susnux](https://github.com/nextcloud/server/pull/66355#issuecomment-6766271914), 10 november 2026):

- De bestaande metadata-API is kaal. De nieuwe API voegt drie dingen toe: een vastgelegd schema, zodat andere apps de gegevens begrijpen zonder de maker te kennen; rechten op metagegevens, waarbij de app die een veld maakt bepaalt wie het mag wijzigen; en later een API om gegevens uit documenten te halen en erin te schrijven.
- Bron per waarde kan via de actor, maar hoort volgens hem in de auditlog, niet in de metagegevens zelf.
- Waarden die een provider zelf aanlevert: metagegevens worden altijd via de API opgeslagen, en die opgeslagen versie is de bron van waarheid. Hij ziet niet waarom een bewaardatum niet zo opgeslagen kan worden.
- Meerdere waarden per veld: mogelijk als er een echte use case is. Nextcloud begint met een basisset typen, omdat een type toevoegen makkelijk is en een type weghalen de API breekt.

**Op issue 66499** ([reactie van susnux](https://github.com/nextcloud/server/issues/66499#issuecomment-6766653823), 10 november 2026):

- Het `fileid` hoort al stabiel te zijn. Is het dat niet, dan is dat een fout die opgelost moet worden. Bestanden die buiten Nextcloud om worden verplaatst, vallen erbuiten.
- `filecache` is geen cache maar de hoofdtabel van het bestandssysteem. Die leegmaken staat gelijk aan het resetten van de installatie. Bij verlies is het antwoord een back-up terugzetten.
- Bij migratie naar een andere installatie gaat de database altijd mee.

Wat dat voor ons betekent: de term "cache rebuild" in issue 66499 was niet goed gekozen. De vraag die overblijft is een identificatie per record die gelijk blijft over versies heen. Onze tests laten wel zien dat bestanden nieuwe `fileid`'s krijgen als de opslag het verwijderen van een map weigert (scenario G in de [testresultaten](../evidence/s3-object-lock-deletes.md)).

## Standpunten van Nextcloud in overleg

Nextcloud gaf in overleg aan dat:

1. bestuurde verwijdering volgens Nextcloud loopt via Nextcloud Governance (retentielabels, legal hold), in de permissielaag;
2. Nextcloud deze cyclus werkt aan bestandsidentiteit op basis van hashes;
3. de schema-API (PR 66355) bedoeld is voor Governance-labels en voor het inbedden van metagegevens in documenten. Een gebruikersinterface laat Nextcloud bewust over aan integratie-apps.

Punt 1 zet keuze (a) uit de [D1-analyse](./d1-analyse.mdx) onder druk. Het besluit daarover ligt bij opdrachtgever en Product Owner. Punt 3 past bij de route die we voor D3 kozen: een integratie-app.
